# Сборка и разработка

[Русский](BUILDING.ru.md) · [English](BUILDING.en.md) · [README проекта](../README.ru.md)

## Поддерживаемый путь сборки

В репозитории предусмотрена сборка и упаковка для Windows на базе MSYS2 UCRT64. Корневой скрипт `build.ps1` предполагает, что инструментарий установлен в `C:\msys64\ucrt64`.

### Необходимые компоненты

- Windows 10 или Windows 11;
- CMake версии 3.24 или новее;
- MSYS2 UCRT64 с GCC, MinGW Make и `objdump`;
- CMake-пакет wxWidgets 3.2 с компонентами `core`, `base` и `gl`;
- библиотеки разработки OpenGL.

| Инструмент или каталог | Ожидаемый путь |
|---|---|
| GCC | `C:\msys64\ucrt64\bin\g++.exe` |
| MinGW Make | `C:\msys64\ucrt64\bin\mingw32-make.exe` |
| Префикс MSYS2 | `C:\msys64\ucrt64` |
| Каталог сборки | `build-native/` |
| Переносимая сборка | `portable/` |

Если MSYS2 установлен в другом месте, измени `$ucrt` в `build.ps1` и передай тот же префикс скрипту `tools/runtime_deps.ps1`.

## Сборка и тестирование

Открой PowerShell в корне репозитория и выполни:

```powershell
./build.ps1
```

Скрипт добавляет каталог UCRT64 `bin` в начало `PATH`, конфигурирует CMake с генератором MinGW Makefiles и конфигурацией Release, собирает GUI-приложение и тесты геометрии, запускает CTest, затем пересоздаёт `portable/`, копирует `GeoTerminal.exe` и собирает необходимые несистемные runtime DLL с помощью `objdump`.

Скрипт удаляет и создаёт заново существующий каталог `portable/`. Перед сборкой закрой запущенный `GeoTerminal.exe`, иначе Windows может запретить замену исполняемого файла.

Для инкрементальной сборки и повторного запуска тестов после конфигурации CMake:

```powershell
cmake --build build-native --parallel 6
ctest --test-dir build-native --output-on-failure
```

Для запуска приложения:

```powershell
./run.ps1
```

`run.ps1` запускает `portable/GeoTerminal.exe`; если файла нет, сначала вызывает `build.ps1`.

## Упаковка runtime-зависимостей

`tools/runtime_deps.ps1` анализирует таблицы PE-импортов с помощью `objdump` из UCRT64. Скрипт рекурсивно копирует необходимые несистемные DLL из каталога UCRT64 `bin` в целевой каталог. Системные DLL Windows и имена API-set не упаковываются.

В переносимом каталоге EXE и его DLL должны находиться рядом:

```text
portable/
  GeoTerminal.exe
  *.dll
```

Не добавляй в пакет случайные DLL из другого окружения компилятора. Набор runtime-зависимостей должен соответствовать EXE, собранному используемым инструментарием.

## Тесты

CTest регистрирует один тестовый исполняемый файл `GeoTerminalTests` под именем `geometry-core`. Он проверяет создание всех 15 типов моделей, топологию сеток и характеристику Эйлера для замкнутых тел, направление нормалей граней, отдельные метрики моделей, осевые/диагональные сечения и сечения по трём точкам, вершины/площадь/периметр сечения шестиугольной пирамиды, точное представление радиан и операции над векторами.

Запуск тестов с выводом ошибок:

```powershell
ctest --test-dir build-native --output-on-failure
```

Текущая автоматизированная цель проверяет геометрическое ядро. Она не заменяет автоматизированное взаимодействие с GUI, визуальные регрессионные тесты или приёмочные испытания установщика.

## Структура исходников

```text
src/
  geometry.hpp / geometry.cpp       Геометрические примитивы, сетки и вычисления
  viewport.hpp / viewport.cpp       OpenGL-сцена, камера, выбор и построения
  trig_circle.hpp / trig_circle.cpp Единичная окружность
  main_frame.hpp / main_frame.cpp   Окно wxWidgets, элементы управления и логика
  main.cpp                          Точка входа приложения
tests/
  geometry_tests.cpp                Регрессионные тесты геометрического ядра
tools/
  runtime_deps.ps1                  Сборщик runtime-зависимостей
```

## Заметки для разработки

- По возможности сохраняй независимость геометрических вычислений от wxWidgets и OpenGL. `geometry.cpp` компилируется и в GUI-приложение, и в отдельный тестовый исполняемый файл.
- Поддерживай воспроизводимую упаковку через `build.ps1` и `runtime_deps.ps1`; не добавляй вручную посторонние runtime DLL.
- `.gitignore` исключает каталоги сборки и логи. `portable/` намеренно хранится в Git, поскольку репозиторий распространяет готовую Windows-сборку.
- При изменении пользовательского поведения или требований к сборке обновляй русскую и английскую версии README и документации.
- Не называй визуализацию сечения булевым разрезанием сетки. Текущая реализация вычисляет многоугольник пересечения по рёбрам модели и рисует его как подсвеченный передний слой.

## Решение типичных проблем

**CMake не находит wxWidgets:** проверь наличие CMake-пакета wxWidgets 3.2 в UCRT64 и значение `CMAKE_PREFIX_PATH`, указывающее на `C:\msys64\ucrt64`. Проект запрашивает компоненты `core`, `base` и `gl`.

**Не найден `objdump` или runtime DLL:** проверь наличие `C:\msys64\ucrt64\bin\objdump.exe` и установку runtime-пакетов UCRT64. Скрипт упаковки намеренно завершается с ошибкой, если не может разрешить несистемную зависимость.

**Не удаётся заменить переносимый EXE:** закрой все процессы GeoTerminal и снова запусти `./build.ps1`. После успешного прохождения тестов скрипт пересоздаёт `portable/`.

**CTest завершается с ошибкой:** запусти тестовый EXE непосредственно из `build-native/` или повтори запуск CTest с параметром `--output-on-failure`. Имя упавшей проверки указывает на геометрический инвариант, который нужно исследовать.
